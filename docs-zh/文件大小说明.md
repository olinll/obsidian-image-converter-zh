# 文件大小说明

本插件会尝试多种策略，并为每张图片选择最小的结果。然后，可以选择在处理后的文件更大时保留原始文件。

## 转换过程中发生了什么

### WEBP/JPEG
- 插件渲染一次，并通过两种浏览器路径编码：
  - `canvas.toBlob(...)`
  - `canvas.toDataURL(...)`
- 对于某些输入，还会与「压缩原始格式」进行比较。
- 选择可用候选中最小的。

### PNG
- 通过以下方式编码：
  - `canvas.toBlob('image/png', ...)`
  - `canvas.toDataURL('image/png', ...)`
- 在适当时也可能与「压缩原始格式」进行比较。
- 选择可用候选中最小的。

### PNGQUANT（仅 PNG）
- 使用您配置的 pngquant 可执行文件。然后在保存时将结果与原始文件进行比较（参见下方「如果更大则恢复原图」）。

### AVIF
- 使用 FFmpeg（libaom-av1），配合您配置的 CRF 和预设。结果也会在保存时与原始文件进行比较。

## 重要：「如果更大则恢复原图」

- 插件使用全局设置代替单个转换的「允许更大的文件」开关：
  - **如果更大则恢复原图**：启用后，如果处理结果大于原始文件，插件将保留原始文件。
  - 默认：关闭
  - 设置位置：设置 → 图片转换器 → 转换预设 → 「如果更大则恢复原图」

## 示例

1) 如果结果为：
   原始：1.0 MB
   WebP (toBlob)：1.5 MB
   WebP (toDataURL)：1.2 MB
   压缩原始格式：0.8 MB
   → 插件返回压缩原始格式（0.8 MB），因为它是最小的。

2) 如果结果为：
   原始：1.0 MB
   WebP (toBlob)：0.6 MB
   WebP (toDataURL)：0.7 MB
   压缩原始格式：0.9 MB
   → 插件返回 WebP (toBlob) 结果（0.6 MB），因为它是最小的。

3) 如果「如果更大则恢复原图」已开启，结果为：
   原始：1.0 MB
   WebP (toBlob)：1.2 MB
   WebP (toDataURL)：1.3 MB
   压缩原始格式：1.1 MB
   → 插件保留原始文件（1.0 MB），因为所有处理结果都更大。

   如果「如果更大则恢复原图」关闭，插件将保存最小的处理结果（本例中为 1.1 MB），即使它大于原始文件。

## 为什么采用这种方式

- **自适应**：为每张特定图片选择压缩效果最好的编码路径。
- **安全**（开启设置时）：不会增大文件大小。
- **实用**：不同图片的压缩效果不同（某些 JPEG 转 WebP 效果更好；某些 PNG 已经是最优的；PNGQUANT/AVIF 根据内容可能效果极佳）。
